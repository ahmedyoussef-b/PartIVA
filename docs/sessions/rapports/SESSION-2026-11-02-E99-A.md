## Constat
- src/core/ai-engine/engine.ts : unEngine enveloppe tout le pipeline dans un seul 	ry/catch générique ; en cas d'échec, retourne des résultats ailed avec warning unique engine_failed, sans message utilisateur actionnable ni détail de l'erreur.

## Risques
- UX : message "Erreur inconnue" non actionnable.
- Debug : perte du contexte d'erreur (stack, étape).
- Masquage : fallbacks partiels (recherche → génération) non exercés car catch global.

## Pistes de correction
A) Normaliser les retours (warnings/errors structurés) — type commun EngineError { code, message, stage }.
B) Centraliser les messages utilisateur dans une map code→message.
C) Durcir les catch critiques avec fallback explicite par étape (ne pas tout avorter).
