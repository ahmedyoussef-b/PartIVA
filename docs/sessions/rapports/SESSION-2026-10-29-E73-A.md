# SESSION-2026-10-29-E73-A — Sauvegarde Locale du Workspace (localStorage)

**Date :** 2026-10-29  
**Feature :** E73-A — Sauvegarde et restauration de l'état du workspace via localStorage, avec bouton d'effacement.  
**Statut :** Implémenté, vérifié (typecheck, lint, format, build EXIT 0). Aucun commit.

## §1 — Contexte

`WorkspaceClient.tsx` gérait un état React complet (photos, cadFiles, dimensions, description, mode, résultat, statut, erreur) mais sans aucune persistance. Le rechargement de la page ou la fermeture de l'onglet faisait perdre tout l'état.

L'Option B (localStorage) a été retenue : simple, rapide, sans modification du schéma Prisma, sans nouvelle route API, et sans risque de régression sur les flux existants.

## §2 — Modifications

### 2.1 Nouveau fichier : `src/lib/hooks/use-workspace-persistence.ts`

Hook client qui gère la persistance de l'état du workspace dans `localStorage` (clé `partiva-workspace-state`).

**État persistant (`PersistedWorkspaceState`) :**
- `photos: string[]` — URLs des photos uploadées
- `cadFiles: string[]` — URLs des fichiers CAO uploadées
- `dimensions` — `{ length?, width?, height?, diameter?, unit }`
- `description: string`
- `mode: 'quick' | 'deep'`
- `result: EngineResult | null` — snapshot complet du résultat du moteur IA

**Comportement :**
1. Au montage : restaure l'état depuis `localStorage` (`JSON.parse` avec try/catch).
2. À chaque changement d'état : sauvegarde dans `localStorage` (`JSON.stringify`).
3. `clearWorkspace()` : réinitialise l'état par défaut et supprime la clé `localStorage`.
4. Les setters (`setPhotos`, `setCadFiles`, `setDimensions`, `setDescription`, `setMode`, `setResult`) acceptent une valeur ou un fonction updater (compatibles avec l'usage existant de `setDimensions` avec callback).

**Non persistés (état volatil conservé en React state) :**
- `extractedDimensions` — dimensions extraites par le viewer 3D
- `status` — statut de soumission (`idle/loading/success/error`)
- `error` — message d'erreur

Extrait :
```ts
export function useWorkspacePersistence() {
  const [state, setState] = useState<PersistedWorkspaceState>(DEFAULT_STATE);
  const isRestored = useRef(false);

  useEffect(() => {
    if (typeof window === 'undefined') return;
    try {
      const raw = localStorage.getItem(STORAGE_KEY);
      if (raw) {
        const parsed = JSON.parse(raw) as Partial<PersistedWorkspaceState>;
        // eslint-disable-next-line react-hooks/set-state-in-effect
        setState((prev) => ({ ... }));
      }
    } catch { /* Ignorer les erreurs de parsing */ }
    isRestored.current = true;
  }, []);

  useEffect(() => {
    if (!isRestored.current) return;
    try { localStorage.setItem(STORAGE_KEY, JSON.stringify(state)); }
    catch { /* Ignorer erreurs de quota ou d'accès */ }
  }, [state]);

  // ... setters et clearWorkspace ...
}
```

## §4 — Risques

- **Aucun impact sur les flux stables** : `useWorkspacePersistence` est un hook isolé, additif. Les appels existants à `/api/engine` et les routes API sont inchangés. Le `result` persiste dans localStorage mais n'est pas renvoyé au serveur.
- **Sécurité** : `localStorage` est accessible uniquement côté client, par l'origine du site. Aucune donnée sensible n'est stockée (pas de tokens, pas de PII utilisateur).
- **Données** : `localStorage` est limité à ~5 Mo par origine. Les URLs Cloudinary et le résultat du moteur (JSON) sont peu volumineux. Le `result` peut contenir des tableaux de candidats et des métadonnées, mais reste bien sous cette limite.
- **SSR/Hydration** : le hook vérifie `typeof window === 'undefined'` avant d'accéder à `localStorage`, évitant les erreurs côté serveur.
