- **MachineType** (lignes 566‑570) : `CNC`, `LATHE`, `PRINTER_3D`

### Relations

- **Machine ↔ Part** (1:n) :
  - Côté Machine : `parts Part[]`
  - Côté Part : `machineId String?` (ligne 93 du modèle Part) avec relation implicite vers Machine
  - Index `@@index([status])` sur la table Machine (ligne 365)

### Logique de compatibilité / capacité

Aucune logique de compatibilité matière ou de "capacité" maximale n'est présente dans le modèle Prisma. Le modèle ne contient que des attributs de base (code, name, type, status, location). Les champs de capacité (charge, charges maximales) sont gérés côté interface (voir section 2) mais ne sont pas contraints au niveau BDD.

## 2. Interface du parc machines (/admin/machines)

### Page de gestion

La page d'administration du parc machines se trouve à l'URL **`/admin/machines`**. Le composant principal est :

- **Fichier** : `src/app/admin/machines/machines-client.tsx` (ligne 1‑202)
- C'est un **Client Component** qui reçoit les données en props (`initialMachines`) et les affiche sous forme de grille de cartes.

### Fonctionnalités de recherche / filtrage

- Le hook `getMachines()` dans `src/lib/data/machines.ts` (lignes 6‑24) accepte des options facettées :
  - `status` : filtre par `IDLE` / `RUNNING` / `MAINTENANCE` / `OFFLINE`
  - `type` : filtre par `CNC` / `LATHE` / `PRINTER_3D`
- Ces filtres sont utilisés côté serveur via les Server Actions `createMachine` / `updateMachine` (via Prisma `findMany` avec `where`).
- Dans l'interface, les stats affichent les compteurs par statut (production, disponibles, charge moyenne) mais il n'y a pas de barre de recherche textuelle libre dans le composant observé.
