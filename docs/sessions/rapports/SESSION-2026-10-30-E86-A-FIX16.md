# SESSION-2026-10-30-E86-A-FIX16

## §1 — Contexte

Correction de l'upload des photos dans `src/components/workspace/IngestZone.tsx` afin qu'elles soient envoyées sur **Cloudinary** (URL `https://` publique) avant d'être transmises à Groq Vision. Le filtre `blob:` ajouté précédemment (E86-A-FIX15) ignorait les URLs `blob:` mais ne résolvait pas la cause : aucune URL publique n'était générée, donc aucune image n'était analysable.

## §2 — Diagnostic

- `IngestZone.tsx`, fonction `simulateUpload` (et son appel depuis l'input file et `FileUploadZone`) utilisait `URL.createObjectURL(file)` comme fallback quand `data.secure_url` était absent ou quand Cloudinary n'était pas configuré.
- Une URL `blob:` est une URL temporaire créée localement dans le navigateur. Elle n'est **pas accessible depuis le serveur** Next.js où s'exécute l'appel à Groq → `TypeError: fetch failed`.
- Résultat : l'avertissement "1 image(s) ignorée(s): URL blob non accessible côté serveur. Aucune image publique valide pour l'analyse." s'affichait systématiquement, bloquant l'analyse d'image.

## §3 — Corrections

### 3.1 `src/components/workspace/IngestZone.tsx`

- Suppression définitive de toute création d'URL `blob:` (`URL.createObjectURL`) dans le chemin photo : l'URL `blob:` n'est plus créée ni ajoutée à l'état `photos`, quel que soit le résultat de l'upload Cloudinary.
- L'upload vers Cloudinary est effectué **avant** d'ajouter l'URL à l'état `photos`, via le pattern existant du projet : `fetch` vers `https://api.cloudinary.com/v1_1/{cloud}/upload` avec `FormData` (`file` + `upload_preset`).
- L'URL `secure_url` retournée par Cloudinary est stockée dans l'état `photos` (URL publique `https://res.cloudinary.com/...`, accessible côté serveur).
- En cas d'échec d'upload ou d'absence de configuration Cloudinary (`NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` / `NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET` non définies), un `console.warn` est émis et l'image est ignorée (pas d'URL locale temporaire inaccessible côté serveur).
- Ajout d'un état `isUploading` (`useState(false)`) avec `setIsUploading(true)` au début de l'upload et `setIsUploading(false)` dans un bloc `finally`, pour gérer l'état de chargement.
- Le bouton "Ajouter des photos" est désactivé (`disabled={isUploading}`) pendant l'upload pour éviter les envois concurrents.

Avant (extrait) :
```ts
urls.push(data.secure_url ?? URL.createObjectURL(file));
// ...
urls.push(URL.createObjectURL(file));
```

Après (extrait) :
```ts
const secureUrl = data.secure_url;
if (secureUrl) {
  urls.push(secureUrl);
} else {
  console.warn('Cloudinary upload succeeded but no secure_url returned', data);
}
```

### 3.2 `src/core/ai-engine/skills/vision/vision.ts` (inchangé, déjà en place depuis E86-A-FIX15)

- Filtrage des URLs en entrée : seules les URLs commençant par `https://` sont conservées (`validUrls`).
- Les URLs `blob:` sont ignorées avec un warning explicite.
- Si aucune image publique valide : `VisionResult` avec `detectedType: null` et warning « Aucune image publique valide pour l'analyse ».
- La boucle de chargement base64 itère sur `validUrls.slice(0, 3)`.
