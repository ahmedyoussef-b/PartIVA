## §1 — Contexte

Lors des tests sur l'IA (analyse de photo et chat dans le workspace), une erreur `404 model_not_found` était retournée par l'API Groq :
```json
{
  "error": {
    "message": "The model `llama-3.3-70b-versatile` does not exist or you do not have access to it.",
    "type": "invalid_request_error",
    "code": "model_not_found"
  }
}
```
L'analyse de l'application de référence (`docs/app`) a été ordonnée pour identifier la configuration et les modèles exacts utilisés en production.

---

L'audit de `docs/app` a révélé les éléments suivants :

1. **Client Groq Web** (`docs/app/src/lib/ai/groq-client.ts`, ligne 4) :
   ```typescript
   const DEFAULT_MODEL = process.env.GROQ_MODEL || 'openai/gpt-oss-120b';
   ```

2. **Configuration Tauri / Rust** (`docs/app/src-tauri/src/embeddings.rs`, ligne 129) :

3. **Formulaire de configuration / Setup** (`docs/app/src/components/setup/setup-form.tsx`, ligne 31) :


Dans toute l'application de référence, le modèle standard Groq par défaut est systématiquement **`openai/gpt-oss-120b`**.

---

## §3 — Différences avec PartIVA et Cause Racine de l'Erreur 404

L'inspection de PartIVA a révélé deux sources de blocage :

1. **Surcharge dans `.env`** :
   À la ligne 103 de `.env`, la variable suivante était explicitement définie :
   ```env
   GROQ_MODEL=llama-3.3-70b-versatile
   ```
   Or `llama-3.3-70b-versatile` est décommissionné par Groq pour les comptes développeurs/gratuits. Même si le code prévoyait un fallback, la présence de cette variable dans l'environnement forçait l'utilisation du modèle décommissionné, provoquant l'erreur 404.

2. **Modèle de Vision obsolète** dans `src/core/ai-engine/skills/vision/vision.ts` :
   ```typescript
   model: process.env.GROQ_VISION_MODEL || 'qwen/qwen3.6-27b',
   ```
   Le modèle `qwen/qwen3.6-27b` renvoie également une erreur 404 `model_not_found` sur l'API Groq. Le modèle multimodal actif et recommandé supportant la vision sur Groq est **`qwen/qwen3.8-27b`**.

---

## §4 — Corrections Appliquées

1. **`src/lib/ai/groq-client.ts`** :
   - Modèle par défaut aligné sur `openai/gpt-oss-120b`.
   - Ajout d'une protection défensive : si le modèle demandé commence par un préfixe obsolète (`llama-`), basculement automatique sur le modèle actif `openai/gpt-oss-120b`.
   ```typescript
   const ACTIVE_FALLBACK_MODEL = 'openai/gpt-oss-120b';
   const envModel = process.env.GROQ_MODEL?.trim();
   const DEFAULT_MODEL =
     envModel && !envModel.startsWith('llama-') ? envModel : ACTIVE_FALLBACK_MODEL;
   ```

2. **`src/core/ai-engine/skills/vision/vision.ts`** :
   - Remplacement du modèle par défaut de vision par le modèle multimodal actif `qwen/qwen3.8-27b` :
   ```typescript
   model: process.env.GROQ_VISION_MODEL || 'qwen/qwen3.8-27b',
   ```

3. **`.env` et `.env.example`** :
   - Mise à jour de `.env` :
     ```env
     USE_GROQ=true
     GROQ_MODEL=openai/gpt-oss-120b
     GROQ_VISION_MODEL=qwen/qwen3.8-27b
     ```
   - Mise à jour de `.env.example` avec ces valeurs recommandées.
