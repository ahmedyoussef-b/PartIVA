E101-F — Reprise après incident `.env` (avec preuves brutes, commandes atomiques)

Contexte :
- Un incident a eu lieu : l'IA Interne a modifié `.env` (commente les URLs Neon), violant le garde-fou. `.env` a été restauré par le Coordinateur.
- Le correctif de `prisma7.config.ts` (priorité `DATABASE_URL` en premier) est en place.
- `run_migrate.cmd` doit être supprimé.
- Le shell de l'IA Interne a des problèmes d'exécution : **chaque commande doit être exécutée UNE PAR UNE, sans `&&`, sans `;`, sans multi-lignes.**

Garde-fou absolu (rappel) :
- **Interdiction** de modifier `.env`, `.env.local`, ou les variables `DATABASE_URL_UNPOOLED` / `DIRECT_URL`.
- **Interdiction** de créer des fichiers hors périmètre (`run_migrate.cmd`, scripts, etc.).
- Si une commande échoue ou si tu ne peux pas l'exécuter : **STOP immédiat**, signaler, ne rien tenter d'autre. **Aucun contournement.**

---

### Étape 1 — Preuves d'état (commandes atomiques)

**Bloc 1.1** :
```

```
→ coller la sortie brute intégrale (doit montrer uniquement l'inversion de priorité sur `DATABASE_URL || DATABASE_URL_UNPOOLED || DIRECT_URL`).

**Bloc 1.2** :
```

```
→ coller la sortie brute intégrale. Vérifier que :
- `prisma7.config.ts` apparaît en `M` (modifié),
- `.env.test` **n'apparaît pas** (non commité),
- `run_migrate.cmd` **n'apparaît pas** (supprimé).

**Bloc 1.3** :
```

```
→ coller la sortie (`False` attendu). Si `True` → supprimer et re-tester.
